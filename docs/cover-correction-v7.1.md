# v0.7.1 표지 수정 — 적용 대상 오해로 대체됨

사용자 후속 설명으로 수정 대상은 표지가 아닌 첫 본문(2페이지)이었음을 확인했다. 이 문서의 표지 문제 중심 전환은 철회하고 [첫 본문 수정](body-opening-correction.md)으로 대체했다. 공통 이미지 비율 처리 수정은 유지한다. 아래 내용은 이전 판단의 기록이다.

사용자는 표지 오른쪽 이미지의 가로 눌림, 이미지 설명의 어색함, 솔루션을 먼저 보여주는 도입 순서를 지적했다. 기존 25장 제안서의 표지를 확인하고 원인을 수정했다.

## 판단과 변경

모든 제안서가 반드시 문제 장면으로 시작해야 하는 것은 아니다. 다만 이 제안은 현장 수요와 적용 조건을 공동조사하는 단계다. AI 장비를 설치한 장면을 먼저 보여주기보다, 울타리로 가려진 출입구에서 차량과 보행 동선이 교차하는 문제를 보여주는 편이 첫 장의 역할에 맞는다. 둘째 장에서 범위·일정·기획 예산·검증 절차를 설명한다.

- 표지 이미지를 장비·경고장치가 없는 문제 장면으로 새로 제작했다. 실제 천안 장소나 사고 사진이 아닌 일반적 관계를 설명하는 생성 개념도다.
- 제목은 ‘천안시 공사장 / SmartFence AI / 보행안전 실증 제안’, 보조 문장은 ‘울타리로 가려진 출입구에서 차량과 보행자가 만납니다’로 정리했다.
- 이미지 위의 흰 설명 띠를 삭제했다. 생성물 고지는 왼쪽 하단에 작게 유지하고, 상세 출처·권리는 메타데이터와 발표자 노트에 보존했다.
- 제안 주관과 기술 협력 회사 표기는 유지했다.

## 비율 문제의 원인

설치된 PptxGenJS 4의 이미지 sizing API는 외부 w/h에 스케일된 원본 치수, sizing.w/h에 출력 프레임 치수를 사용한다. 기존 코드가 양쪽에 같은 프레임 치수를 넣어 잘라낼 부분이 없는 것으로 계산했고, 원본이 다른 비율일 때 프레임에 맞춰 눌렸다. `coverFit`이 원본 비율을 유지한 스케일과 중앙 크롭을 계산하도록 고쳤다. 차량·보행자·출입구를 자르지 않는 거의 정사각형 원본을 표지 프레임에 맞췄다.

현재 출력 프레임만 비교해서는 이미지 왜곡을 찾을 수 없다. 원본/크롭 후 비율 검사, 와이드 원본의 크롭 단위 테스트, 실제 PPTX `a:srcRect` 검사, 렌더링 확인을 추가했다. API 키나 외부 모델 API 호출은 사용하지 않았다. 생성 이미지와 기록은 `examples/assets/cover-crossing-problem-v8.png`, `examples/assets/provenance-v8.json`에 있다.

재생성 시 `scripts/refine-decision-design.ts`가 새 표지의 계획·이미지·문구를 다시 반영한다. 다른 장의 본문이나 사업 수치는 이번 표지 수정으로 바꾸지 않았다. 공통 이미지 함수 수정은 원본과 출력 비율이 다른 이미지에 정상적인 크롭을 적용한다.

## 검증 기록

최종 실행 `2026-10-27T11-03-52-614Z-edd692`. TypeScript 및 단위 테스트 56개 통과. 5장·25장 통합 검사는 통과했고, 7장 변환은 최초 시간 초과 후 단독 재실행에서 정상 통과했다. 최종 25장 출력 QA 오류 0건. 표지 이미지 1254×1254px를 7.38×7.5in 프레임에 좌우 각각 0.8% 크롭해 배치했으며, 실제 출력에서 차량·사람·울타리 비율과 주 피사체 보존을 확인했다. 이미지 설명 띠와 오른쪽 캡션이 없고 왼쪽 하단에 짧은 생성 개념도 고지만 남는 것을 확인했다. 재생성 전후 입력 JSON 동일성 및 프로젝트 스킬 검증도 통과했다. 자동 검사를 최종 사업·안전 승인으로 해석하지 않으며 `finalApproval=false`를 유지한다.
