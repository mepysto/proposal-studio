# v0.4 — 페이지별 시각 설명과 반복 가능한 제작 규칙

기존 상세 제안서는 사업의 구성 요소를 보강했지만, 본문이 긴 표·문단으로 남아 시각적으로 이해하기 어려웠다. 이번에는 질문에 대한 답을 먼저 시각 관계로 설계하고 본문을 그 주변에 짧게 배치했다. 25장의 구성은 유지했다.

주된 표현은 다이어그램 중심 18장, 이미지 중심 5장, 수치 차트 중심 2장이다. 이미지 중심 장표에도 편집 가능한 번호·설명은 별도로 배치했다. 각 그림은 단순 장식이 아니라 해당 질문의 공간·시간·인과·경계·선택을 설명한다. 수치가 없는 지표는 성공률 게이지나 채워진 비율로 꾸미지 않았다.

## 영속화한 범위

- `AGENTS.md`: 다음 작업자가 이 프로젝트의 제안서 작업에서 재사용 스킬을 읽도록 지정한다.
- `skills/proposal-visual-storytelling/SKILL.md`: 사용자가 반복 지시하지 않아도 적용할 시각 설명 기준, 도구 선택, 현장/개념 구분, 검수 절차.
- `planning.visualPolicy`: 모든 페이지에 시각화 계획과 실제 출력이 필요하다는 실행 가능한 정책.
- `planning.story[].visualPlan`: 종류·요약·표현 논리·근거·노드·관계·범례·일정 구간.
- `examples/smartfence-visual-plans.json`: 이번 사례의 재현 가능한 집필 데이터. 새 사업에서는 장소·주체·일정·지표를 다시 설계해야 한다.
- `visual-plan.json`: 내보낸 결과와 함께 확인할 페이지별 시각화 계획과 자산 종류.

메모리의 범위는 이 프로젝트다. 개인 계정 전체의 전역 스킬이나 모든 대화의 기억을 수정했다고 주장하지 않는다. 프로젝트 지침이 스킬을 불러오는 역할을 한다. 새 문서의 완성본은 시각화 정책을 유지해야 하며, 검사 통과를 위해 정책을 끄거나 빈 도형을 넣지 않는다.

## 적용한 외부 지침

이미 설치된 Presentations, imagegen, skill-creator 지침을 읽고 적용했다. 프로젝트 원 지시서가 명시한 PptxGenJS와 PowerPoint 도형/SVG 사용을 우선하여 다이어그램·텍스트·차트의 편집 가능성을 유지했다. 공간 장면만 내장 imagegen으로 생성했다. 별도 모델 API나 API 키는 사용하지 않았다. 외부 스킬 전체를 복사하거나 불필요한 플러그인을 설치하지 않았다.

새 이미지 2종의 프롬프트·출처·역할은 `examples/assets/provenance-v4.json`에 보관했다. 실제 천안역세권·오룡지구 사진이나 조사된 배치도가 아니며 장표에도 그 사실을 표시했다.

## 검사와 한계

계획이 없는 페이지, 잘못된 근거·연결, 장표 수용량 초과, 누락 이미지, 정의하지 않은 일정 범위를 차단한다. 기획과 제작 장표의 시각화 데이터가 다르면 오래되거나 임의로 변형된 결과로 본다.

렌더링 검사는 페이지별로 이미지/차트 또는 실제 표시 요소가 있는 다이어그램의 구성 영역을 확인한다. 이 사례의 최소 구성 영역은 전체 페이지의 16%다. 이는 도형 잉크 면적이나 의미적 품질 점수가 아닌 휴리스틱이다. 계획만 있거나 빈 영역만 선언한 경우, 작은 장식선만 있는 경우는 통과하지 못한다. 자동 검사 후 전 장을 렌더링해 시각적 의미·연결 방향·문구·자산 크롭·수치 해석을 확인해야 한다.

기존 사업 근거와 세부 설명은 원래 구조화 입력·검토 문서에 보관하고, 관련 섹션 전체를 PPTX 발표자 노트에도 넣었다. PDF에는 핵심 시각 설명과 그 해석에 필수적인 한계를 남긴다. 자동 검사가 전문가의 안전 판단, 실제 현장 적합성 또는 최종 승인을 대신하지 않는다.
