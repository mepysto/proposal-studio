# v0.7 — 읽히는 설명에서 판단 가능한 제안으로

v0.6은 지도·차트·인과 도식을 갖췄지만, 장표별 시각 자료가 있다는 사실만으로 사업 결정에 충분한 문서가 되지는 않았다. 이번 수정은 기존 25장 구성과 확인된 지역 자료를 유지하면서 의사결정에 필요한 내용을 구체화했다. 새 현장조사·견적·성능 검증·외부 전문가 승인을 수행했다고 표시하지 않는다.

| 발견한 약점 | 수정 |

## 디자인 판단

반복된 세 카드보다 표·단계 막대·정상/장애 흐름을 선택했다. 요약의 짙은 색 정보 띠로 범위·일정·예산·요청의 위계를 만들고, 역할표는 이름보다 업무와 확인 문서를 먼저 읽도록 배치했다. 제목은 핵심 주장과 판단을 짧게 표현하도록 정리했다. 회사명·제목 기준선·지도 비율·단위·출처·가정 고지는 유지했다. 출처 코드는 가능한 한 사람이 읽는 기관명으로 바꾸고 상세 서지는 동봉 기록으로 연결했다.

새로운 사진을 추가하거나 기존 개념도를 실제 천안 현장 사진으로 바꾸지 않았다. 지도는 여전히 동/시설 참고점이며 출입구·사업 경계 실사가 아니다. 과거 사고 수치의 감소와 SmartFence 성과를 연결하지 않는다. 예상 가치를 약속된 성과로 제시하지 않는다.

## 재사용과 구현

`businessCase.deliveryAssurance`는 협의 전의 후보 기준·산출물·역할·장애 대응·착수 관문·현재 요청을 저장한다. 장표의 새로운 종류는 각각 의미에 맞는 렌더러를 사용한다. 일정 단계·담당자·출처의 참조와 실제 실행 도식 렌더링을 검사한다. 새 절차와 조건은 `business-case.md`와 `visual-evidence.json`에 함께 내보낸다.

`scripts/refine-decision-design.ts`가 기존 근거 시각화 적용 후 이번 검토 내용을 재적용한다. 외부 모델 API 없이 작성자가 검토한 예제이며, CLI가 자동으로 조사하거나 독립 전문가 여러 명을 실행하는 기능은 아니다. 다른 제안서에 적용할 때 천안의 후보·기간·회사·예산·절차를 그대로 복사하면 안 된다.
