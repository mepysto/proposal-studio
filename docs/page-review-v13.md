실제 PNG 비교에서 바뀐 페이지는 **8·20·23·24·25**이며 나머지 21장은 이전 검토본과 동일하다. 바뀌지 않은 페이지도 이번에 읽을 수 있는 전체 출력으로 다시 확인했다. 첫 제작에서 20/23장의 긴 문구가 자동 넘침 검사에 걸려 패키지 이미지/범위를 재배치하고 텍스트 상자 높이를 조정했다. 중요 글자를 축소하거나 검사를 끄지 않았다.

새 장면 생성은 필요하지 않았다. 20장은 기존 운전자 LED 장면을 공급 범위의 기준으로, 23장은 전광판과 동일한 보행 영상을 시연 대조의 기준으로 재사용한다. 각 `scene.reuseReason`에 목적을 기록했다. 24장은 기존 OSM 투영/좌표 근거를 그대로 사용한다. 사업 계획/가정/현장 결과의 경계는 유지한다.

## 재발 방지를 위한 체계 변경

1. **스킬 분리**: 짧은 진입 지침에서 기획·검토, 제작, 천안 사례의 세 참조 문서로 연결한다. 회사·지역 사실을 다른 사업에 복사하지 않도록 분리했다.
2. **최신 규칙 통일**: AGENTS/README/구조 문서의 25장·초기 엔진 소개와 누적 충돌을 정리했다. 현재 관제명, 둥근 강조 블록, 제공 로고/연락처, 생성 경위의 메타데이터 기록을 명확히 했다. 초기 구조 설명은 역사 기록으로 보존한다.
3. **기획 입력 확장**: 26장마다 `explanation`에 판단 과제, 읽는 방법, 입증하지 않는 사항과 필요한 실제 시각 요소를 작성한다. `requireExplanationContract`는 현재 상세 예제에서 활성화하고 이전 5/7 예제에 강제로 적용하지 않는다.
4. **출력 대조**: 실제 선택한 장면 경로, 지도/차트 ID, 의미 연결선, 비교 행, 인식·통제 표시, 일정 범위와 실제 로고를 확인한다. 필요한 요소가 빠지면 QA/export를 차단한다. 무관한 스톡 이미지나 색상 카드로 대체해도 해당 장면으로 인정하지 않는다.
5. **추적·재현**: `visual-adequacy.json`을 export하고 `visual-evidence.json`·decision brief에도 설명 계약을 보존한다. 새 레시피 `refine-visual-adequacy.ts`가 예제 재생성 후에도 26장 개선을 적용한다.

면적/존재 검사는 의미나 미적 완성도를 자동 평가하지 못한다. 실제 읽힘 검토는 이 기록으로 남기며, 자동 보고서는 `readable-page-inspection-required`와 `finalApproval: false`를 유지한다. 현장 사진·제품 시험·설치 수요가 새로 확인되면 관련 지도/장면/비교 자료를 갱신해야 한다.

최종 타입/단위/통합/출력 검증과 run 정보는 [v13 검증 기록](validation-v13.md)에 있다.
