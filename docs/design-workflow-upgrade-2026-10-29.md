# Proposal Studio 디자인 제작·검수 기능 개선

2026-10-29. 현재 저장소와 설치된 스킬/플러그인을 살펴본 뒤 구현한 내용. 외부 모델 호출, 자료 업로드, 독립 전문가 검토는 수행하지 않았다.

## 확인한 결손과 적용

시각 계획·실제 mark 대조·근거 계약·기하 검사는 이미 존재했다. 반면 출력과 함께 열 수 있는 페이지별 읽힘 검수 화면, 해당 출력의 변경 여부를 확인하는 검수 기록 계약은 없었다. 과거 markdown 검토 이력은 가치가 있지만 새 렌더에 그대로 승계할 수 없다.

`packages/design-review/index.ts`와 CLI `design-review`를 추가했다. build/export가 생성하는 로컬 HTML은 전체 PNG, 독자 과제, 읽는 방법, 입증하지 않는 사항과 메타데이터 진단을 페이지별로 묶는다. 네트워크/외부 패키지 없이 작동한다. 텍스트는 HTML escape하며 이미지는 실제 미리보기 파일명을 사용한다. 구형 5/7장에도 설명 계약을 강제하지 않는다.

작성자가 기록한 페이지별 유지/수정/보류·관찰·근거/미확인·검토자·시간을 입력받는다. 설정/PPTX/PDF와 각 PNG의 SHA-256으로 묶어 누락·중복·이전 출력 기록을 거부한다. 반복 실행은 작성 기록을 덮지 않는다. 보류는 별도 상태로 남고, 검수 기록도 finalApproval을 true로 바꾸지 않는다. 자동 QA 통과 후 export 가능 여부는 이전과 같다. 검수 미완료는 별도 inspection-status에 드러난다.

기존 프로젝트 스킬에 `references/design-direction-and-inspection.md`를 연결했다. 연속 장표의 정보 역할, 관계에 맞는 구성, 큰 시각물/진입점/읽는 순서, 내용 축약 우선, 실제 장면·연결선·화면 상태 검토와 접근성 검토의 한계를 정리했다. 출처는 해당 문서의 W3C/Microsoft 공식 지침에 있다.

## 현재 25장 적용 관찰

최신 run `2026-10-28T23-07-58-860Z-cff4fd`에 기존 PPTX/PDF/PNG를 바꾸지 않고 검수 파일을 추가했다. 25장 모두의 계획 mark 누락은 0이며, 설명 영역의 16pt 미만 텍스트가 있는 페이지는 17장이다. 이는 중요 텍스트 오류 개수가 아니라 점검 대상이다.

진단이 많이 잡힌 14·16·18장의 원본 1600×900 PNG를 직접 열었다:

| 페이지 | 관찰 | 이번 판단 |
|---|---|---|
| 14 운전자 화면 | 객체 박스/장비 프레임/출차 대기/세 상태가 보인다. 작은 글자는 객체 라벨·운전자 확인·화면 조건에도 사용된다 | 일괄 확대는 화면 관계를 훼손할 수 있어 적용하지 않음. 실제 설치 화면 가독성은 별도 검증 필요 |
| 16 장애 대응 | 정상 경로와 장애 행의 담당/재개 조건이 연결된다. 담당 회사·조치 문구가 상대적으로 작다 | 본문과 보조 정보의 위계 차이로 기록. 중요 조치인지에 따른 후속 편집 판단 필요 |
| 18 일정 | 실제 기간 바·산출물·검수 문구가 대응된다. 작은 숫자는 월 축 눈금 및 보조 산출물에 포함된다 | 축 라벨까지 실패로 판정하면 안 됨. 진단을 권고로 유지 |

나머지 22장의 실제 PNG를 이번 작업에서 다시 읽었다고 주장하지 않는다. 이번에는 고객 장표의 문구/레이아웃·프로젝트 입력·기존 자산을 변경하지 않았다. 검수 template은 25장 모두 pending으로 유지했다. HTML의 구조·링크/escape는 테스트했지만 브라우저 보안 정책이 file URL 열기를 차단했고 로컬 HTTP 서버도 sandbox에서 허용되지 않아 실제 브라우저 조판 확인은 미완료다.

## 스킬·플러그인 판단

Plugin Management에서 `presentation design PowerPoint typography`를 검색했다. Figma와 Google Drive는 설치됨으로 반환됐다. 이 확인은 개별 계정 연결/쓰기 권한 검증을 뜻하지 않는다. Canva는 디자인/브랜드 검토 기능을 제공하는 설치 가능 후보지만 계정 연결 및 기능에 따른 AI credit 조건이 있고, 현재 PPTX 오프라인 제작에서 빠진 기능을 해결하기 위해 꼭 필요하지는 않다. SharePoint/HeyGen/MagicPath 역시 현재 작업에 필요한 근거가 없어 추가하지 않았다. 플러그인은 설치 개수가 아니라 구체적 결손을 기준으로 선택한다.

현재에는 Presentations·professional-drawio·내장 imagegen·skill-creator와 프로젝트 스킬 보강으로 진행했다. 새 npm 의존성/플러그인 설치 및 권한 변경은 없다. 외부 스킬 전문을 복사하지 않았다.

## 검증

- 타입 검사 통과.
- 단위 테스트 92개 통과, opt-in 통합 3개는 단위 실행에서 skip.
- 추가 테스트는 출력 변경에 따른 무효화, 누락/중복 페이지, 보류 상태, 원본 기록 보존, 미검수/승인 구분, HTML escape를 검증한다.
- 실제 5·7·25장 전체 통합 테스트 3개 통과. PPTX→PDF→PNG→export, 단일 장표 재생성 시 전체 출력 보존, 25장 근거·브랜드·공개 명칭·연락처·편집 가능 차트의 기존 검증을 유지했다.
- skill-creator quick_validate는 사용 가능한 두 Python 환경 모두 PyYAML이 없어 실행되지 않았다. 대신 기존 YAML frontmatter의 필수 메타데이터와 연결된 참조 파일 존재를 확인했다. 이를 bundled validator 통과로 표현하지 않는다.
