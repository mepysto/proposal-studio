# 콘셉트와 실제 장표 구도를 연결한 구현·검증

2026-10-31. [진단 문서](concept-design-diagnosis-2026-10-31.md)의 제안에 따라 구현했다. Codex 작성자가 저술·코드 변경·출력 검토를 수행했으며 독립 전문가/다중 모델 검토나 최종 승인이 아니다.

## 구현

- `packages/art-direction/schema.ts`: 제안별 designDirection, 페이지별 compositionBrief. 핵심 아이디어·시각 번역·브랜드 제약·참고자료 해석, 역할·읽는 순서·구성 이유·실제 영역을 저장한다. 미지원 버전/키는 거부한다.
- `packages/planning`: story→slide로 구도를 그대로 복사하고, 콘셉트가 있는 프로젝트의 디자인도 기획 fingerprint에 반영한다. 실제 출처와 연결되지 않은 참고 해석, 빠진 노드/라벨 배치, 영역 충돌, 기획과 달라진 구도를 검사한다.
- `packages/art-direction/tokens.ts`: 요청마다 별도 팔레트를 해석한다. professional-kit과 전문 제작 모듈이 공통 전역 객체를 수정하지 않고 사용한다. 콘셉트가 없는 legacy는 이전 값 그대로다.
- `authored-composition.ts`: 장면·지도·네이티브 차트·관계도·대안 비교·기간 바를 저술한 영역에 배치한다. 사업명별 분기를 추가하는 방식이 아니다. 영역 비율을 바꿔 같은 관계를 가로/세로로 설명할 수 있다. 기존 지도/수치/시각 정책을 보존한다.
- QA: 특정 제목 x좌표를 강제하는 legacy 검사는 새 구도에서 선언 영역·정렬·위계 대조로 바뀐다. 둥근 핵심 강조/큰 글자/부분 강조와 브랜드·근거·실제 mark·기하 검사는 유지한다. 실제 노드/관계/라벨 출력도 확인한다. 실제 제목·강조 영역이 반복되는 경우는 visual kind가 달라도 진단한다.
- 초기/출력 기록: `design-plan`, `design-storyboard.md`, `art-direction-plan.json`, run/output의 `art-direction.json`, manifest, config, visual-plan, PPTX notes와 검수 HTML에 콘셉트와 구도를 보존한다. 기존 run의 검수 파일 보완도 지원한다.

작성 방법과 정확한 지원 범위는 [구현 계약](../skills/proposal-visual-storytelling/references/authored-compositions.md)에 있다. 새 스킬 전문 복사·플러그인 설치·npm 의존성 추가·API 키·외부 모델 호출은 없다. 프로젝트 스킬은 최신 기능을 반영하고, 구현 전 진단은 이력으로 구분했다.

## 실제 제작한 별도 예제

`examples/concept-direction.project.json` / `projects/concept-direction/project.json`. 기존 고객 제안서와 다른 7장 제작 예제다. 현재 색·좌표는 이 예제의 저술 결정이며 새 공통 템플릿이 아니다. `scripts/create-concept-example.ts`는 기존 근거/자산에서 예제 입력을 다시 만들며 기존 고객 프로젝트를 수정하지 않는다. `npm run demo:direction`은 로컬 편집본이 없을 때만 초기화하며 이후 로컬 편집을 보존한다.

최종 run: `2026-10-31T01-09-48-043Z-9aadb1`. editable PPTX, PDF, 7개 PNG, 근거/시각 mark/QA/디자인·검수 기록을 생성했다. 최종 원본 PNG 7장 모두 1600×900 크기로 열어 읽었다. 접촉 시트만 보고 완료로 처리하지 않았다.

| 장 | 실제 관찰 | 판단/수정 |
|---|---|---|
| 1 공간 | 큰 현장과 오른쪽 제목/핵심 문구. 원본 비율, 차량·보행자·유도원 주석 대상 확인 | 유지. 원본 개념 장면에 editable 주석, 실제 현장/실측 아님 조건 유지 |
| 2 근거 | 차트가 오른쪽 주 영역, 해석 경계는 왼쪽. 전체/보행자를 나란히 비교 | 유지. 34·27·17·13과 기간/단위/모집단/2차보도·중첩 집계 한계 확인 |
| 3 흐름 | 가로 노드·실제 경계에 붙는 연결·관계 라벨 | 유지. 경고 발송과 실제 통제는 구별 |
| 4 확인 | 같은 관계를 세로로 배치해 완료 확인을 강조 | 라벨을 세로 연결선 가까이 이동하고 최종본 재확인 |
| 5 지역 | 지도 A/B/C, 오른쪽 이름, 스케일/북쪽/출처와 실사 한계 | 유지. 원본 투영 자산과 같은 transform 사용 |
| 6 비교 | 같은 대응 범위/한계 기준으로 세 대안 비교 | 흐름용 범례를 비교 해석 한계로 교체, 실제 대안과 노드 결합도 검사 |
| 7 기간 | 1·2·4·1개월 길이와 산출물의 대응 | 단일 기간을 1개월차/8개월차로 자연스럽게 정리 |

실제 출력 해시와 연결한 작성자 검수 기록을 등록했다. 기록 완결성과 finalApproval은 별개이며 false를 유지한다. PowerPoint 앱에서 실제 읽기 순서/대체 텍스트/태그 PDF 검사를 수행했다고 주장하지 않는다. HTML의 정보와 escape/링크는 테스트했으나 이번에도 브라우저 조판을 별도로 검수한 것은 아니다.

## 호환성과 검증

- TypeScript 타입 검사 통과.
- 단위 테스트 99개 통과. opt-in 통합 4개는 단위 실행에서 skip.
- 실제 PPTX→PDF→PNG→export 통합 4개 통과: 기존 5장, 기존 7장, 현재 Cheonan 27장, 새 구성 예제 7장. 마지막 예제 수정 후 해당 통합을 다시 실행해 통과했다.
- 렌더 테스트에서 선언 영역과 실제 요소 위치/크기, 다른 구도의 같은 관계, native chart의 실제 값, 팔레트 동시 렌더 격리, 이전 구도 무효화, 미지원 결합 거부와 반복 geometry 진단을 확인했다.
- SmartFence의 기존 최신 run `2026-10-30T08-37-08-018Z-0a948e` config를 새 코드로 임시 PPTX에 재렌더했다. 전체 elements.json이 같고 **27개 slide XML 모두 원본과 동일**했다. 임시 결과는 비교 후 제거했다. 따라서 새 예제만 새 구도를 사용하며, 현재 고객 제안의 27장 레이아웃을 덮어쓰지 않았다.
- 기존 SmartFence/SafeSurface/SLT/SafeHome의 시각 계약 테스트를 유지했다. 이 기록은 다른 제안의 모든 PNG를 이번에 다시 읽었다는 뜻은 아니다.
- 프로젝트 스킬의 연결 참조 파일을 확인했다. skill-creator의 Python validator는 기존 환경의 PyYAML 부재 문제를 해결하거나 새 패키지를 설치하지 않았으며, 해당 validator 통과로 주장하지 않는다.

## 남는 범위

이 기능은 저술한 콘셉트와 구도를 실행·검증한다. 자유 문장을 읽어 자동으로 독창적 디자인을 발명하는 엔진은 아니다. 새 제안의 브리프/시안 저술은 여전히 필요하다. 복잡한 장애물 회피 경유점 라우팅, 자유로운 다축 제품 비교, 특수 제품 화면/실패 상태/인과/비용 계약의 범용 대체는 지원하지 않는다. 이 경우 의미 계약을 유지해 전용 구현을 확장해야 하며 unsupported 오류를 없애려고 라벨·관계·정책을 삭제하지 않는다. named tokens 이외에 과거 사례에 직접 지정된 모든 색/좌표까지 자동 테마화한 것은 아니다.
