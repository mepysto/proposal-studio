## 저술 순서의 세부 개선

1. 먼저 열람 조건과 결정할 사람을 정한다. 회의실 발표인지 사전 배포인지, 이번에 요청할 결정이 무엇인지 기록한다. 투자자 자료의 시장/성장/수익 구조를 공공 안전 제안에 기계적으로 이식하지 않는다.
2. 페이지 목록을 만들기 전에 독자의 질문을 배열한다. 각 페이지가 이전 이해에서 무엇을 더 알게 하는지와 다음 질문을 정한다. 지원하지 못하는 결론은 조건부 판단이나 조사 과제로 남긴다.
3. 주 시각물을 정하고, 그 안에서 주목할 대상을 선택한다. 큰 제목/색/카드는 그 관계를 찾기 쉽게 돕는다. 빈 영역이나 장식만으로 설명 계약을 채우지 않는다.
4. 레퍼런스의 목적·지면·청중을 확인한다. 원리 하나를 자기 근거에 맞게 적용하고 채택하지 않을 요소를 적는다. 외부 문서의 사실/로고/제품/증언은 자기 제안 근거가 아니다.
5. 대표 페이지에서 제목→시각 근거→조건을 실제로 읽어본다. 레이아웃을 바꿨는데도 독자의 질문에 답하지 못하면 문구보다 의미 구조를 먼저 고친다.
6. 정보량을 줄일 때 판단을 바꾸는 조건/단위/기간/출처는 지키고 세부 설명을 읽기용 근거 문서로 옮긴다. 중요한 글자를 줄이지 않는다.

## 실제 적용 예제

별도 `examples/reference-direction.project.json` / `projects/reference-direction`을 만들었다. 기존 27장 고객 제안서와 직전 concept-direction 예제의 입력·출력은 덮어쓰지 않았다. 7장 모두 기존 사업 근거와 자산을 사용한다. 외부 PDF·그림·고객 로고·숫자는 예제 PPTX에 넣지 않았다.

- 1장: 장면 옆 제목을 36pt, 원칙 문구를 22pt로 지정했다. 전환 시점의 무게를 주되 장면 설명과 개념 한계를 유지한다.
- 2장: 도시 전체와 보행자 집계의 실제 값은 유지한다. 보행자 계열을 강조하고 같은 원자료 값을 직접 표기한다. 부분집합을 누적하지 않고 현장 효과로 표현하지 않는다.
- 3장: 같은 실제 대응 경로를 open 노드로 구성한다. 의미 없는 새 선을 만들지 않고 기존 송수신·확인 관계와 라벨을 유지한다.
- 4장: 비교 기준이 되는 세로 관계도는 그대로 유지해, 표현 변경이 목적에 필요한지 판단할 수 있게 했다.
- 5장: 지도와 A/B/C 설명 영역을 직접 지정한다. 같은 투영 변환과 출처/스케일/참고점 의미를 유지한다.
- 6·7장: 대안 비교와 실제 기간 바는 유지하고, 페이지 질문·판단 변화·다음 질문을 기획 기록에 보강한다.

현재 지원 계약은 [참고 원리 적용 가이드](../skills/proposal-visual-storytelling/references/reference-led-design.md)에 있다. 복잡한 기능을 추가하는 플러그인이나 외부 모델 API를 연결하지 않았다.

## 검증과 제한

타입/단위 테스트, 실제 PPTX→PDF→PNG, 원본 크기 시각 검수와 해시 결합 기록은 아래 최종 실행 결과에 기록한다. 자동 존재/기하 검사나 직접 검토를 전문 디자이너 승인으로 표현하지 않으며 finalApproval은 false다. 접근이 실패한 후보는 catalog의 excluded에 기록하고 검토했다고 주장하지 않는다.

### 최종 실행 결과

- TypeScript 타입 검사 통과.
- 단위 테스트 101개 통과. 기존 5/7/27장 및 콘셉트 7장 통합 4개, 새 참고 적용 7장 통합 1개가 각각 통과했다. 합계 5개 실제 PPTX→PDF→PNG→export 검증이다.
- 최종 예제 run: `2026-10-31T01-30-14-167Z-4582bf`. 7개 원본 1600×900 PNG를 읽었고, 문구를 고친 2장은 최종본을 다시 읽었다. 나머지 1·3·4·5·6·7장은 직전 읽은 run과 PNG 해시가 동일했다.
- 1·2·3·5장 표현을 수정하고 4·6·7장 시각 구성을 유지한 판단을 페이지별로 기록했다. 실제 출력 해시에 연결한 작성자 검수 기록을 등록하고 finalApproval:false를 유지한다.
- 차트 강조는 native chart XML의 원래 34·27·17·13 값 보존과 함께 검사했다. 없는 계열/근거·참고 설정 누락·잘못된 지도 영역·본문 누락·잘못된 글자 위계는 탐지한다. 데이터 해석의 진실성/가독성/전문성은 자동 승인하지 않는다.
- 외부 참고 파일을 예제의 이미지 자산으로 넣지 않는 테스트를 추가했다. 참고자료는 실제 사업 근거와 별도 source/applicability로 구분한다.
- 코드·스킬의 연결 참조를 확인했다. PowerPoint 앱 및 HTML 브라우저 조판을 별도로 확인했다고 주장하지 않는다.
