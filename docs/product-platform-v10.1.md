# 두 제품과 통합관제의 구성

사용자의 후속 정정에 따라 대외 제안서는 특정 회사의 보드 제작을 전면에 내세우기보다 3사 협력 제품의 기능과 공공사업 활용을 설명한다. 제안 주관 (주)에스엘티 및 기술 협력 표기는 유지한다. 세부 제조 이력은 기존 출처 원장에 남기며 NPU 칩 자체 제조로 확대하지 않는다.

## 제품별 역할

- **자체 제작 AI NPU 안전관리 장치**: 사람·차량 인식, 위험 조건 분석, 현장 음성·주의 알림. NPU는 제품에 탑재된 분석 기반이다.
- **컬러 LED AIoT 전광판**: 센서 데이터·CCTV 연계, AI 콘텐츠 생성, 안전·공사정보 및 공공 목적 광고 표출. 단순 NPU 출력 화면이 아닌 자체 기능을 갖춘 제품이다.
- **비트리 통합관제**: 두 제품의 상태·이벤트·장애, 표출 편성·운영 설정, 조치 이력과 운영 보고를 함께 관리하는 제품을 제안한다. 세부 연동·설정 범위는 시연·설계 과정에서 확인한다.

앞의 제품 역량은 사용자 제공 설명이다. 평상시에는 공사·공공정책·행사 등의 정보를 편성하고 위험 발생 시 안전 안내를 우선하는 것은 이번 제안의 운영 설계다. AI 콘텐츠는 담당자 검토 후 게시하며, CCTV는 권한 있는 내부 수신자 화면으로 제한한다. 실제 공공 표출과 운전자 내부 화면은 방향·대상별로 편성을 구분한다. 공공광고를 유료 광고 매출이나 조례·게시 허가 확보로 표현하지 않는다.

## 문서 구성

표지는 ‘천안시 공공사업 공사현장’으로 범위를 명확히 했다. 3페이지는 두 현장 제품과 통합관제의 전체 구조, 12페이지는 제품별 자체 기능, 15페이지는 영상·센서에서 두 제품으로 병렬 연결되는 흐름과 통합 운영을 보여준다. 14페이지는 내부 안전 화면의 3상태와 평상시 정보/위험 시 우선 표출을 구분한다. 후반에는 안전·공공정보의 활용, 도입 패키지, 장비 회수·재설치, 운영서비스와 시연 판단을 연결한다. 첫 본문 문제 페이지는 그대로 보존한다.

`businessCase.productPositioning.platform`은 두 제품, 비트리 관제, 표출 우선순위와 콘텐츠 검토 경계를 구조화한다. 제품 ID 중복·없는 근거를 검사하고, 흐름도는 새 5노드 병렬 구성의 실제 레이아웃 용량을 적용한다. 기존 6노드 정보 흐름과 5/7페이지 예제는 유지한다. `scripts/refine-product-platform.ts`가 앞선 제작 레시피 뒤에 이 사용자 정정을 적용하므로 전체 입력 재생성에도 보존된다.
