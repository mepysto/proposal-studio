# Proposal Studio v0.3 — 사업기획을 먼저 검토하는 제작 체계

## 기존 방식의 문제

문제–개입–검증 연결과 깨끗한 조판만으로는 사업제안서가 완성되지 않는다. 기존 7장 초안은 일반적인 안전 논리를 설명했지만 왜 천안인지, 어느 현장에서 시작할지, 누가 운영할지, 비용과 공공가치를 어떻게 판단할지 충분히 답하지 못했다. 출처가 연결됐다는 구조적 검사도 내용의 전문성을 보증하지 못한다.

이번에는 문장을 늘리기 전에 지역 조사, 분야별 검토, 상충 의견의 조정, 후보지 비교, 실행·예산·성과 모델을 작성하고 이를 25장의 의사결정 흐름으로 편집했다. API 키와 런타임 LLM 호출은 사용하지 않았다. Codex가 이번 대화에서 조사하고 집필한 구조화 입력을 오프라인 엔진이 재현한다.

## 집필 전 검토 순서

1. **발주자의 결정 정의**: 현 단계 요청은 도시 전체 도입이 아니라 후보 현장 공동조사와 제한 실증의 협의다.
2. **지역 맥락과 근거 원장**: 천안의 실제 공개 사업·정책을 확인하고 주장 단위로 출처, 확인일, 적용 한계를 기록한다. 확인한 과거 사업계획은 현재 공정이나 계약 가능성을 입증하지 않는다.
3. **목적별 관점 설정**: `requiredDisciplines`로 필요한 분야를 정한다. 이 사례는 도시기획, 현장안전, 공공디자인, 시스템설계, 스마트시티, 사업성·평가의 6개 관점이다. 모든 사업에 같은 직업 목록을 고정하지 않는다.
4. **각 관점의 검토**: 문제, 근거, 제안, 수용 조건, 반영 장표를 작성한다. 외부 전문가가 실제 참여한 것처럼 표시하지 않는다. 현재 `reviewer`는 `assistant-perspective`만 허용한다.
5. **관점 사이의 조정**: 보행 접근성 대 차량 통제, 경고 주목성 대 생활 불편, 도시 연계 대 초도 복잡도, 기존 장비 재사용 대 성능을 비교하고 선택 이유와 미확인 조건을 남긴다.
6. **장소별 가설**: 공개 사업의 주소·기능과 실제 출입구·차량·보행량·관리권한을 구분한다. 현장 관찰 근거가 있어야 `surveyed`로 표시할 수 있다.
7. **사업 모델**: 범위, 일정, 주체, 비용, 제외 비용, 기대효과, 측정 계획, 진입·보류·중단 조건을 작성한다.
8. **편집과 제작**: 장표마다 질문–답–근거–시각화 목적–한계를 연결한다. 표·관계도·설치 개념도·운영 흐름·비용 차트·효과 체계를 해당 설명에 맞춰 선택한다.
9. **자동 검사와 렌더링 검토**: 구조 오류는 해당 단계로 돌려보내고, PPTX→PDF→PNG를 실제 생성해 한글·페이지별 텍스트·겹침·폰트·페이지 수를 확인한다.

## 천안 사례의 판단

- 천안역세권 혁신지구(와촌동 106-83 일원): 복합 기능과 보행 접점을 고려한 우선 **조사** 후보다. 실제 출입구와 공정, 설치 허용 여부는 미확인이다.
- 오룡지구 리츠사업(원성동 31-70 일원): 생활권 접점과 복수 관리 주체를 함께 살펴볼 예비 후보다.
- 봉명지구 도시재생(봉명동 39-1 일원): 분산된 재생사업이 단일 차량 출입구 실증에 맞는지 확인하기 전까지 보류한다.

세 곳 모두 실사 전이다. 후보 관계도에는 실제 좌표·축척·거리·방향·출입구 위치를 부여하지 않았다. 실제 위치를 아는 것처럼 만든 지도나 현장 사진을 사용하지 않는다. 생성 이미지는 실제 천안 현장·설치안이 아닌 개념도라고 표시한다.

일반 안전 근거는 위험 구조와 기본 조치의 필요성을 설명한다. 천안의 사고율이나 특정 현장의 위험 빈도를 입증하는 데 사용하지 않는다. 현장조사, 통제 시험, 장비 적합성 및 관계부서 검토가 필요한 항목은 완료 처리하지 않는다.

## 구현 구조

| 계층 | 입력·출력과 책임 |
|---|---|
| `business-case/schema.ts` | 지역 맥락, 분야별 검토, 조정 결정, 후보지, 비용 범위, 효과·지표, 장표 섹션 |
| `business-case/index.ts` | 참조·필수 장·장수·분야 누락·실사 오표기·예산·수용량 검사, 합계·시간 산식, 검토 기록 생성 |
| `planning` | 기존 문제–원인–대안–개입–검증 모델과 상세 사업 모델을 통합하고 내용 지문으로 오래된 장표 탐지 |
| `pptx-renderer/business.ts` | 구조화 데이터로 편집 가능한 표·관계도·시스템·일정·비용·효과·KPI·결정 장표 제작 |
| `quality-assurance` | 좌표와 텍스트 검사, PDF의 해당 페이지에 텍스트가 남았는지 검사 |
| `document.py` | 모든 페이지의 텍스트·폰트 검사와 PNG 렌더링 |
| `core/pipeline.ts` | 분석·제작·내보내기에 `business-case.md`와 원장·검사 결과 포함 |

`planning.depth = full`은 지역형 제안에 검증된 지역 주장 3개 이상, 지정 분야의 검토, 실제 스토리에 포함된 필수 사업 장, 목표 장수의 일치를 요구한다. 표·이미지 옆 설명 등의 수용량을 초과하면 내용을 조용히 생략하지 않고 차단한다. `concept` 깊이는 이전 7장 검토 경로를 유지한다.

검사 통과는 구조와 출력의 일관성에 대한 결과다. 인과관계의 타당성, 전문가 판단의 수준, 실제 안전 효과, 현장 적합성을 자동 증명하지 않는다. `finalApproval`은 계속 false다.

## 수치를 다루는 기준

기준 예산은 7,200만원, 범위 4,500만~1억800만원으로 **기획 가정**이다. VAT 10% 가정 시 기준 총액은 7,920만원이다. 확정 견적·천안시 편성 예산·계약 제안가가 아니다. 장비뿐 아니라 통합, 설치 지원, 교육, 약 4개월 현장 운영·평가를 포함한다. 전체 울타리 시공, 추가 토목·전력 증설, 공기 연장, 연간 유지보수 등은 별도다. 표·차트·합계는 같은 숫자 모델에서 계산한다.

시간 절감은 20건/일 × 20일/월 × (5−2)분 ÷ 60 = 월 20시간이라는 **계산법 예시**다. 모든 입력이 가정이며 목표나 실측 성과가 아니다. 인력 감축·현금 절감·사고 감소액으로 환산하지 않는다.

실증 지표는 위험사례 미탐률, 실제 경고장치 작동까지의 p95 지연, 조치 기록 완결률이다. 오탐·반복 알림·운영자 업무·시민 불편을 함께 본다. 미측정 기준선과 미합의 목표는 `null`로 보관한다. 임의의 0, 정확도 99%, 사고 감소율을 삽입하지 않는다. 실제 행인에게 위험을 발생시키는 시험 대신 안전하게 통제된 시나리오로 검증한다.

## 재현과 남은 한계

`npm run demo`는 `examples/smartfence-full.project.json`으로 25장 결과를 만든다. 이미 프로젝트가 있으면 로컬 편집본을 재사용한다. `scripts/create-smartfence-full.py`는 이번에 작성한 입력을 재구성하는 개발 도구이며, 새로운 원문을 읽어 자동 조사·집필하는 LLM이 아니다.

현재 개선은 구조화된 사전 검토를 요구하고 실제 사례를 충분히 작성해 재현한 것이다. 임의의 새로운 사업에 대해 자동으로 전문가를 선택하거나 최신 지역자료를 찾아 판단하는 기능은 아직 없다. 웹 확인은 이번 대화에서 수행했고 CLI 자체는 검색을 실행하지 않는다. 다음 자동화는 이 계약에 맞는 조사·집필 결과를 공급해야 하며, 출처 확인이나 현장 관찰을 대신했다고 주장해서는 안 된다.
