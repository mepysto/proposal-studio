# 천안시 담당자 관점의 제안 내용 재검토

기획 검토의 기준은 페이지마다 담당자가 품는 질문에 답하는지, 그 답이 사업의 공익·도입 범위·실행 가능성·지속 활용으로 이어지는지다. 작성자가 기획 관점에서 검토했으며 독립 전문가나 천안시의 승인으로 표시하지 않는다.

## 문제와 변경

종전 후반부는 업무 역할표, 과거 축소안 비용, 검수·승인 조건과 수식에 무게가 쏠렸다. 필요한 내부 관리 자료지만 본문에서는 도입 가치와 실행 범위를 충분히 설명하지 못했다. 근거·예산의 불확실성을 반복하는 것만으로 합리적인 사업이 설명되지는 않는다.

이미지의 생성 도구 표시는 슬라이드에서 제거한다. ‘제안 설치 예시’, ‘화면 예시’는 표현 대상과 해석 범위를 설명하는 짧은 이름으로 사용한다. 실제 천안 현장 사진, 이미 설치한 제품 또는 검증된 성능으로 주장하지 않는다. 생성 출처와 권리는 메타데이터·이미지 원장·노트에 보존한다.

## 전 페이지 검토와 구성

|페이지|담당자 질문 / 편집 판단|
|---|---|
|1|누구의 어떤 사업 제안인가? 주관사·협력사·사업 소개 유지|
|2|무슨 문제가 있는가? 출입구 동선 충돌과 시야 가림 유지|
|3|전체 사업은 무엇인가? 중복 권역 지도 대신 양방향 안내→설비 재투입, 규모·기간·비용 상태 제시|
|4|천안시 맥락은 무엇인가? 보행안전 지표 유지. 도시 수치와 현장 수요 구분|
|5|어디서 문제가 생기는가? 출입구 공간 예시 유지|
|6|누가 어떻게 행동하는가? 차량·시민·현장 대응 흐름 유지|
|7|어디부터 조사하는가? 후보 권역 지도와 조사 우선순위 유지|
|8|왜 그 현장인가? 위험 노출·운영 가능성 기준 유지|
|9|와촌동의 어떤 조건을 확인하는가? 위치·설치 가설 유지|
|10|원성동 대안은 무엇인가? 위치·관리 권한·주민 동선 유지|
|11|기본 안전조치보다 무엇을 더하는가? 동선 분리·통제·AI 보완의 구분 유지|
|12|무슨 장비가 누구에게 작동하는가? 제품 구성 유지|
|13|기능은 어떤 원인을 어떻게 보완하는가? 개입과 현장 반응 유지|
|14|운전자는 무엇을 보는가? LED 영상·감지·공사정보와 확인불가 상태 유지|
|15|정보가 어디로 가는가? 카메라→현장 제어기→외부 음성/내부 LED, 운영 기록→시 집계 보고로 전면 재구성|
|16|장애 때 안전은 어떻게 지키는가? 수동 통제·복구 구조 유지|
|17|보행자는 무엇을 듣고 보는가? 외부 알림 장치와 음성 예시 유지|
|18|얼마나 걸리는가? 8개월·단계별 산출물 유지|
|19|시민·현장·시에 무엇이 남는가? 역할표를 공익과 운영 자산의 기대효과로 교체|
|20|무슨 범위로 얼마를 검토하는가? 1개 출입구 실증 패키지와 견적 구성. 과거 축소안 금액/차트는 본문 제외|
|21|공사 뒤에도 쓸 수 있는가? 회수·점검·보관·다음 현장 검수 유지|
|22|시가 매일 관리해야 하는가? 시 판단/공급사 단일 서비스 창구/현장 안전책임의 관계로 교체|
|23|계속할 가치는 어떻게 판단하는가? 성능 수식 나열을 작동·현장 변화·재사용 총비용의 질문과 관찰 근거로 교체|
|24|천안시 사업으로 어떻게 이어지는가? 승인표를 대표 현장 실증→다음 현장 재투입→수요별 순환 운영 경로로 교체|
|25|무엇을 함께 추진할 것인가? 현장 공동조사→배치/서비스/견적 구체화→실증과 다음 활용의 추진안으로 교체|

## 논리와 근거

시민의 인지 기회 확대, 현장의 확인 절차 일관성, 시의 재사용 자산·운영 경험 축적은 기대효과 가설이다. 사고 감소율이나 경제성의 실측 결과로 쓰지 않는다. 기능은 미탐·실제 작동 지연, 현장 가치는 조치 기록·추가 업무·불편, 지속 활용은 이전·수리·보관·재설치·유휴기간으로 판단한다. 미측정 상태를 임의 숫자로 채우지 않는다.

8개월/현장 운영 약4개월과 출입구 1개소는 기존 기획 기준이다. 현장별 장비 수량·LED 규격·전력·지원 기간을 정한 후 확장 견적이 필요하다. 소유·보관·계약은 미확정이다. 과거 비용/내부 역할표/세부 승인 조건은 동봉 검토 기록에 남기고 본문의 중심 서사에서 제외한다.

`businessCase.municipalCase`와 `scripts/refine-municipal-case.ts`에 논리·내용을 보존했다. 자동으로 전문가가 검토·조사하는 기능이 아니라 이번 대화에서 작성한 검토안을 오프라인 재적용하는 방식이다.
