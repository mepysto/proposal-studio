# SmartFence 제안서 문안 편집 기록

편집일: 2026-10-27. API 없이 현재 대화의 Codex가 기획·문안 편집 역할을 수행함.

원본 Markdown, 근거 주장, 검증 상태와 출처 확인일은 유지했다. 시범사업 제안과 실제 설치·실증 성과를 구분하고, 새로운 수치·성과·지역 사실을 추가하지 않았다.

## cover

이전 제목: 공사차량 출입구 / 보행안전 실증

수정 제목: 공사장 출입구 / AI 보행안전 / 시범사업 제안

핵심 내용: 차량·보행자 접근을 알리고, 유도원의 현장 대응과 기록을 돕습니다.

편집 이유: 제안 대상과 사업 성격을 바로 알 수 있게 제목을 정리하고, 추상적인 관측·조치 연결 표현을 줄임.

## problem

이전 제목: 출입구에서는 시민과 공사차량의 동선이 겹친다

수정 제목: 공사차량 출입구의 보행자 충돌 위험

핵심 내용: 차량 출입로와 보도가 만나는 구간은 동선 관리와 시야 확보, 유도원의 통제가 함께 필요합니다.

편집 이유: 일반적인 위험을 설명하는 페이지임을 분명히 하고, 차량 출입로와 보도가 만나는 상황을 본문에서 설명.

## risk

이전 제목: 충돌 위험을 보는 기준은 동선과 시야다

수정 제목: 차량 동선과 사각지대를 현장에서 먼저 확인합니다

핵심 내용: 차량과 보행자가 어디서 만나는지, 서로를 보기 어려운 곳은 어디인지, 유도원이 어디서 통제할지 확인합니다.

편집 이유: 평가자의 관점처럼 들리던 제목을 현장 조사에서 실제로 확인할 행동으로 바꿈.

## alternatives

이전 제목: AI 도입 전에 기존 대응의 잔여 과제를 본다

수정 제목: AI는 동선 분리와 현장 통제를 보완합니다

핵심 내용: 동선 분리와 유도원 운영을 먼저 점검하고, 접근 알림과 대응 기록을 더할 필요가 있는지 확인합니다.

편집 이유: 잔여 과제·관측 과제 같은 내부 분석 용어를 줄이고 기존 안전조치와 AI 보조의 역할을 설명.

## concept

이전 제목: 장비 배치의 목적은 현장 조치 지원이다

수정 제목: 차량·보행자 접근을 알리고 유도원의 대응을 돕습니다

핵심 내용: 카메라와 현장 분석장치, 담당자 경고장치를 연결하고 조치 결과를 기록하는 구성을 제안합니다.

편집 이유: 장비 배치의 목적이라는 추상적 제목을 감지·알림·유도원 지원이라는 구체적인 기능으로 바꿈.

## operation

이전 제목: 경고 전송과 현장 안전확인은 다르다

수정 제목: 경고가 울린 뒤 실제 조치가 있었는지 확인합니다

핵심 내용: 시스템은 위험을 알리고, 유도원은 통행을 관리합니다. 경고 전달과 현장 조치 여부를 각각 확인합니다.

편집 이유: 경고와 안전확인이 다르다는 선언을 넘어 경고 후 실제 조치를 확인한다는 업무로 설명.

## validation

이전 제목: 측정 결과로 도입과 확대 여부를 결정한다

수정 제목: 한 곳에서 먼저 검증한 뒤 확대 여부를 결정합니다

핵심 내용: 후보 현장에서 감지 성능과 경고 전달, 현장 대응을 시험하고 관리 효과와 운영 부담을 함께 평가합니다.

편집 이유: 단계적 적용 방식을 제목에서 드러내고 감지·전달·대응의 평가 항목을 자연스러운 질문으로 정리.

## 함께 고친 표현

- 기준라벨 → 사람이 표시한 정답
- 종단 지연 → 감지부터 경고까지 걸린 시간
- 실동작 → 실제 작동
- 검증 가능한 원장 → 위험 발생·현장 대응 기록
- 접근 관측·조건 판단 → 차량·보행자 감지

API나 자동 LLM 어댑터를 호출하지 않았다. 문안은 프로젝트의 planning에 반영하고 기존 plan/build/review/export 경로로 제작한다.


## 렌더링 후 문장 배치 보완

설치 설명은 감지·알림·기록 각각을 두 줄 안에서 읽히도록 다듬었다. 검증 질문은 짧게 줄이고 확대 보류 조건은 의미 단위로 줄을 나눠 문장 끝 한 단어만 남는 현상을 줄였다.
