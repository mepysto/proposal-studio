# 구조와 구현 범위

## 실행 경로

`CLI → init → ingest → analyze → plan → build(PptxGenJS) → LibreOffice PDF → Poppler PNG → QA → export`

`core`가 실행과 이력을 조정합니다. Zod로 입력을 검증하고, `content`가 원본을 보존하며 추출 결과를 해시 캐시로 저장합니다. `agents`의 오프라인 규칙은 근거 목록과 확인 과제를 만들고 `storyboard`가 제공 장표 또는 원문 발췌를 선택합니다. `design-system`과 `visual-assets`는 스타일·이미지 브리프를 저장합니다. 렌더러는 네이티브 텍스트·도형·차트를 만들고 좌표를 기록합니다. QA는 좌표와 실제 PDF의 텍스트·폰트·페이지를 함께 검사합니다.

각 사업은 `project.json`으로 주입합니다. 엔진에 SmartFence 이름, 천안 정책, 회사 역할 또는 특정 산업의 본문을 하드코딩하지 않았습니다. SmartFence의 전문 문구와 5장 구성은 `examples/smartfence.project.json`에 있습니다.

## 설계 경계

- 원본과 사용자 설정은 보존하고 실행마다 고유 디렉터리에 기록합니다. 새 프로젝트 초기화는 기존 설정을 덮어쓰지 않습니다.
- 내용·디자인 참고·자산 역할을 분리합니다. 참고 PDF의 사진을 추출해 무단 재사용하지 않습니다.
- 중요한 주장은 canonical claim ID로 연결합니다. 승인과 외부 검증을 구분하며, PDF 발표자 노트에 주장 상태와 출처를 남깁니다.
- 숫자·예산의 의미적 정합성 엔진은 아직 없습니다. 구조화 주장 연결이 수치 모순을 모두 잡는다는 주장은 하지 않습니다.
- API 어댑터는 계약만 정의했습니다. 역할 이름을 나열한 것은 실제 LLM 에이전트를 실행했다는 의미가 아닙니다.
- PptxGenJS는 렌더러에만 종속됩니다. 미래의 대체 렌더러는 PPTX와 요소 좌표 명세를 반환하면 QA와 연결할 수 있습니다.
- 한글 폰트 접근을 위해 프로세스 한정 fontconfig와 임시 사용자 프로필을 사용합니다. 설치된 LibreOffice 설정을 변경하지 않습니다.
- 실패 run은 추적을 위해 남깁니다. `latest.json`은 최신 전체 실행, `latest-slide-<id>.json`은 개별 실행입니다. 자동 승인·배포·외부 공유는 하지 않습니다.

## 단계별 상태

| 단계 | 이번 구현 | 남은 일 |
|---|---|---|
| Phase 1 | CLI, 자료 보존·추출, 발췌 플래너, 구조화 장표, 5종 실물 장표, PPTX/PDF/PNG/시트, 기본 QA, 테스트 | 다양한 사용자 원문과 Office 버전으로 회귀 검증 확대 |
| Phase 2 | 역할별 인터페이스, 오프라인 근거 목록, 이미지 브리프, 내장 도구로 생성한 예제 이미지, 네이티브 차트 | 사용자 승인 후 LLM·검색·이미지 Provider 구현, 실제 조사·전략 분석·모델별 검수 |
| Phase 3 | 실행 버전·원본 해시·캐시·개별 장표 출력, PDF 메타데이터 분석 | 18개 독립 레이아웃, 참고문서 시각 분석 자동화, 자동 수리, 의미적 수치 검증, 비전 QA |
| Phase 4 | import 가능한 core API | 로컬 웹 UI, HTTP API, 템플릿 관리, 프로젝트 비교, BusinessOS 연동 |

외부 API 없는 Core MVP를 우선 완료한다는 사용자 지시에 따라 키 생성이나 비용이 드는 API 호출을 요구하지 않았습니다. AI 연동 단계에서는 제공자·키 사용 승인을 받은 후 실제 실행을 검증해야 합니다. 현재 결과물은 전문 기획을 수행하는 완성형 AI 플랫폼 전체가 아니라 실행 가능한 제작 엔진과 검증된 초기 예제입니다.

## v0.2 확장

현재 기본 데모는 `smartfence-v2`입니다. 기획·의사결정·대안·검증의 계약, 근거 적용 범위, 질문/답/근거 스토리보드 컴파일러, 설명 목적별 공간도·개입 번호·책임 스윔레인과 기획 QA를 추가했습니다. 상세 내용과 현재의 제한은 `docs/pipeline-v2.md`에 있습니다. 위 Phase 표는 v0.1 시점 기록이며, v0.2도 외부 LLM·검색·이미지 API가 연결되었다는 뜻은 아닙니다.
